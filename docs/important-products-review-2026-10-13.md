## Homepage presentation directions

The references below are linked from the supplied [Digital Gravity article](https://www.digitalgravity.ae/blog/top-best-website-ui-ux-designs/). They inform the presentation, not claims about EL AMAL's ranking or design awards.

| Direction | Appearance and interaction | Reference and suitability |
| --- | --- | --- |
| Product gallery — recommended | Three real instruments isolated against navy, each with its own composition, pale-blue lighting and generous space. A small pointer tilt and controlled scroll entrance add depth. White type and the existing orange calls to action stay consistent. | [Gufram](https://gufram.it/en/) demonstrates object silhouettes and varied scale without ordinary photo boxes. This adapts well to industrial instruments. |
| Three product chapters | Each featured instrument gets a larger editorial section with a concise specification and a soft transition into the next. Mobile uses normal vertical scrolling. | [Jeton](https://www.jeton.com/) provides a reference for a large focal object and strong visual hierarchy. More dramatic, but increases homepage length. |
| Technical close-up | Large authentic detail crops reveal the dial, connection or valve body, with a few useful specifications beside them. Keyboard-accessible detail controls replace decorative hotspots where necessary. | [Osmo](https://www.osmo.supply/) shows preview compositions and interaction examples including product hotspots and shutter transitions. Best when accurate close-up assets are available. |

The recommended four-layer concept is: real instrument as subject; pale-blue light against deep navy; asymmetric, oversized framing; technical confidence and care as the emotional effect. The motion should help the eye locate a product and understand a choice.

Use clean manufacturer assets for the selected models where available. These photographs preserve the catalogue evidence, but their small printed images, perspective and pen marks limit enlargement quality. Any background removal must retain the instrument's real dial, connections, finish and proportions. Layered photographs can create convincing depth without a heavy 3D scene. A genuine 360-degree rotation needs accurate multi-angle images or a suitable model; one photograph cannot establish the unseen geometry.

Performance requirements for implementation: responsive optimized images, reserved image dimensions, lazy loading below the fold, transform-based movement, no added WebGL requirement, static reduced-motion treatment and a simple touch layout. Measure the deployed result before claiming a performance score. Nour retains visual approval.

## Arabic and English SEO

The current application already generates localized product titles and descriptions, canonical links, English/Arabic language alternatives, Product/WebPage/breadcrumb data and bilingual sitemap entries for valid published catalogue records. Each new record still needs accurate bilingual copy, manufacturer model codes, technical specifications, image descriptions and the correct datasheet.

The additions should target the actual instrument and its use naturally. For example, pressure gauge copy can use “WIKA pressure gauge” and “مقياس ضغط ويكا” alongside the exact model; connection labels must also be present in readable page content. Arabic pages should contain substantive Arabic descriptions, not English copy with translated navigation. Keep existing valve URLs intact and connect new pages to their relevant categories. This follows Google's [localized-page guidance](https://developers.google.com/search/docs/specialty/international/localized-versions).

Keep one canonical family page per language, with both choices available on that page. Evaluate ProductGroup/hasVariant only after the actual configurations are defined. Google's [variant documentation](https://developers.google.com/search/docs/appearance/structured-data/product-variants) describes both single-page and multi-page approaches. It does not justify invented prices, offers, reviews or stock for a quotation-only catalogue, and markup alone does not guarantee search placement.

Release checks should cover both language pages, linked datasheets, readable option text, canonical and reciprocal language links, structured data, sitemap inclusion and image loading. Product-specific social preview images can follow the selected homepage assets.

## Implementation notes

The public Product and CatalogueDetails types currently have no option model. The file `src/content/product-options.ts` defines search filters, not variants. The catalogue-details parser allowlists fields, so unrecognized option JSON would be discarded.

The implementation must extend the validated catalogue data and public projection, key basket lines by product plus option, resolve option labels against trusted catalogue data on the server, and preserve an immutable option snapshot in enquiry items. Do not put connection choices into the measurement-range field. Keep product-level click-through reporting attached to the existing product identity.

The homepage currently selects the first product in each category. Replace this with an explicit selection of the three confirmed records and a dedicated featured presentation. Other products remain in their normal category pages.

The September importer is pinned to its original 90 in-stock and 61 out-of-stock groups. Prepare a separate dated batch and targeted upserts; do not rerun it blindly. Retain source-photo provenance and verify current manufacturer specifications before publication. One example requiring care is that pressure ranges in an older catalogue can differ from a current manufacturer's family page.
